# 任务：钉钉聊天记录工作复盘 + 原始资料打包归档钉盘 + Excel 台账生成

> **这是什么**：一段可选进阶提示词。把它发给带钉钉命令行工具（`dws`）的 AI 助手，它会把指定时间范围内「你发出的」钉钉消息拉全量，复盘成工作主线报告 + 脱敏聊天流水 + Excel 台账，打包上传钉盘归档。
>
> **依赖说明**：文中命令面向 WorkBuddy 自带的 `dws` 命令行工具（`dws chat +search-msg` / `dws drive +upload` 等）。如果你的环境里没有这个工具，**保留七步框架，把 dws 命令替换成你自己环境里的消息检索与文件上传方式即可**——流程（拉取 → 解析会话 → 聚合 → 归档 → 台账 → 交付）与工具无关。
>
> **口径提醒**：统计的是「你发出的消息」，不含仅接收未回复的内容，可能低估部分事项；附件默认不下载。这两条限制建议在每次交付时向使用者重申。
>
> 来源：王树辉私有环境工作流（2026-10），整理入本模板时仅补充依赖说明与降级路径，命令与流程原样保留。

## 输入参数

- 复盘时间范围：{{例如：最近一个月 / 2026-08-28 至 2026-09-28}}
- 被复盘人姓名：{{姓名}}
- 是否下载消息内的图片/文件附件：{{默认不下载，仅归档消息文本；用户明确要求才开}}

## 第一步：拉取全量消息（只取"我发出的"）

1. 优先使用结构化检索（可全量翻页、可按发送者过滤）：
   ```
   dws chat +search-msg --sender "{{姓名}}" --start "<RFC3339>" --end "<RFC3339>" --limit 100 --page-all --page-limit 40 --no-reactions --format json
   ```
   - 如需同时归档附件图片/文件，追加：`--download-resources --output-dir ./output/resources`（必须是工作目录内相对路径）；否则不加，不要自行下载。
   - 每条 dws 命令都带 `--format json`，只按真实返回下结论。
2. 校验完整性：`complete=true` 且 `hasMore=false` 才能称"全量"；否则只能表述为"本次返回 N 条"，并保留 stopReason/failures 说明。
3. 若该命令不可用或权限不足，降级用行为回溯：
   ```
   dws aisearch behavior --queries "" --types im --behavior-type send --time-range "{{时间原文}}" --format json
   ```
   （返回的是聚合片段，覆盖度低于 search-msg，需在结论里注明口径差异。）

## 第二步：解析会话身份

1. 拉会话列表：`dws chat +conversation-list --page-all --format json`
2. 用返回的 openConversationId → conversationName 建立映射表，把每条消息的 cid 还原成"和谁聊/哪个群"。
3. 注意：conversationName 在群聊是群名、单聊是对方名字；不要按消息正文猜会话。

## 第三步：聚合分析

用 python3 脚本处理原始 JSON（不要肉眼读全量），产出：

1. 按会话分组：条数、起止日期、消息密度 → 识别核心协作对象（Top 3~5）。
2. 按主题分线：从消息文本聚类"工作主线"，每条线回答四问：做了什么（动作）/ 什么状态（产出、上线、下证、发布等事实）/ 卡在哪（阻塞、驳回、待决策）/ 和谁协作。
3. 事实校验：只总结有明确消息证据的内容；"计划做/建议"不能写成"已完成"；时间以 createTime 为准。
4. 敏感信息处理：验证码、账号凭证、身份证/银行卡信息不进入总结和 Excel；聊天流水 md 中替换为 [敏感信息-已略去]；原始 JSON 中保留但按第七步提醒用户自行保管。

## 第四步：原始资料归档（本地暂存到 output/）

必须生成到工作区 output/，临时目录（如 /tmp）的文件不算交付：

1. `output/raw/messages_{{起}}_{{止}}.json` —— search-msg --page-all 的全量原始返回，不改动、不删减（机读证据源）。
2. `output/raw/conversations.json` —— 会话列表原始返回，用于 cid→名称回查。
3. `output/聊天流水_{{姓名}}_{{起}}_{{止}}.md` —— 人类可读逐条流水：按会话分节，每条一行，格式「MM-DD HH:MM 内容摘要（≤110字）」；标注 [图片][文件][通话][卡片]，附件计数；此文件为脱敏版。
4. （仅当第一步开了附件下载）`output/resources/` —— 下载的媒体文件；交付说明列出成功数/失败清单（failures ledger），下载失败条目注明"原始文件未归档"。

## 第五步：打包并上传钉盘（最终交付通道）

1. 将第四步全部材料 + 第六步 Excel 打成一个压缩包：
   ```
   {{姓名}}_钉钉复盘资料_{{起}}_{{止}}.zip
   ```
   zip 内保留目录结构（至少含 Excel、聊天流水 md、raw/），散件不删除。
2. 上传到用户钉盘（默认进"我的文件"）：
   ```
   dws drive +upload --file <zip的相对路径> --format json
   ```
   - 本地路径必须是工作目录内相对路径，禁止绝对路径和 .. 逃逸。
3. 写后回查（不能只凭命令成功下结论）：
   按返回的真实 nodeId 执行 `dws drive +inspect --node <dentryUuid> --format json`，核对文件名完整、大小与本地 zip 一致；不一致或无法验证时不得宣称已上传。
4. 在最终答复中列出：钉盘文件名、nodeId、所在位置；若上传失败，说明原因并保留 output/ 本地散件作为兜底交付（用文件卡片逐个展示给用户）。
5. 钉盘临时下载 URL 不作为交付物外发。

## 第六步：生成 Excel 台账（保存到 output/，并随 zip 一起进钉盘）

用 xlsx 技能（openpyxl）建「{{姓名}}_工作复盘_{{起}}_{{止}}.xlsx」，4 个 sheet：

1. 「总览」：时间范围、消息总数、会话数、完整性标志（complete/hasMore）、各主线编号/名称/一句话进展/状态（进行中-已完成-受阻），并加一行说明"原始证据见钉盘 zip 内 raw/ 与聊天流水 md"。
2. 「工作主线」：一条主线一行，列 = 主线、关键动作与产出、里程碑事件（含日期）、当前阻塞、主要协作人、涉及会话。
3. 「会话明细」：一个会话一行，列 = 会话名称、类型（群聊/单聊）、我发的条数、起止日期、主题摘要（≤80字）。
4. 「消息流水」：全量数据，列 = 时间、会话、消息类型（文本/文件/通话/卡片）、内容摘要（≤110字，附件标注[文件][图片][通话]）。

格式要求：表头加粗+填充色、冻结首行、自动筛选、主线状态列条件着色、日期列标准时间格式。

## 第七步：交付与收尾

1. 正文输出 Markdown 复盘报告（先一句话总结，再按主线展开）。
2. 用文件卡片展示：钉盘上传成功确认信息 + Excel 本体（zip 已在钉盘，散件可按需展示）。
3. 提醒用户：raw JSON 为未脱敏原始记录，请注意保管。
4. 明确标注数据口径：统计的是"你发出的消息"，不含仅接收未回复的内容，可能低估部分事项；附件仅显式开启时归档。

## 硬性约束

- 不猜命令、参数、字段和 ID，全部以 JSON 真实返回为准；unknown flag 时查一次该命令 help 修正。
- 空结果或失败不能被总结成"没做这件事"，需注明"本次检索未命中"。
- 分页未走完、有 failures 时，总结、Excel 和钉盘交付说明里都要保留该说明。
- 钉盘上传必须走"上传→按 nodeId 回查文件名和大小"两步，验证通过才算交付完成；partial_success 不算完成。
- 所有中间产物放临时目录，所有交付物必须落 output/ 并最终进钉盘包；其他位置的文件用户拿不到。
