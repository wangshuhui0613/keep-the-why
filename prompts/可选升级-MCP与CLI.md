# 可选升级：MCP 与 Obsidian CLI

> 这是**可选项**。不装任何外部服务，这个知识库已经完整可用——本页只回答一个问题：想让 AI 助手**直接操作 Obsidian**（而不是只会写文件）时，有哪些路、各自的规矩。

## 两条路线

### 路线一：Obsidian 官方 CLI

Obsidian 已提供官方命令行工具（见 Obsidian 官方帮助的 CLI 文档）。装了它，AI 助手可以直接执行「打开库、建笔记、按模板插入」这类操作，不再只是往目录里写 Markdown 文件。

适合：已经在用 Claude Code / Codex 等 Agent，希望「说一句话就建好一篇规范日记」的人。

### 路线二：MCP Server（如 mcpvault 一类）

MCP（Model Context Protocol）是 Agent 连接外部工具的标准协议。社区有若干 Obsidian MCP server（如 bitbonsai/mcpvault），装上后 Agent 可以获得「搜索库、读笔记、写笔记」的工具能力。

适合：库变大之后，希望 AI 先搜索再回答、而不是每次全库翻找的人。

## 选了任何一条，规矩都不变

无论走 Skill 路线（AI 按规则写文件）还是 CLI/MCP 路线（AI 直接操作 Obsidian），下面这些一律照旧：

1. **根目录 `AGENTS.md` 是最高规则**。CLI/MCP 只是换了操作入口，不换规则：写入分流、五类编号、十字段、原始层只读，全部适用。
2. **原始层只读**。`02-工作经历/04_日报素材/`、`05_文档原文/`、`07_附件/` 不许经任何途径修改。
3. **`.obsidian/workspace.json` 永不进 Git**。它是界面状态，只属于这台电脑。
4. **危险操作先问用户**。经 MCP 删除、批量改写、移动文件，和手动做一样，必须先确认。
5. **不要把「已下载」写成「已安装」**。装没装上，以能跑通一次真实操作为准。

## 我们的立场

这个模板本身**不开发、不绑定任何 MCP server 或 CLI**——零依赖是刻意的选择：一堆标准 Markdown 文件，任何工具没了你都能继续用。上面两条路是给「已经感到痛点」的人的升级方向，不是入门要求。
