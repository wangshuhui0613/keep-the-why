# 一键构建指令

> 把下面代码块里**从「开始」到「结束」的整段**复制给你的 AI 助手（Codex、WorkBuddy、Claude、Cursor 等都可以），
> 允许它检查环境并创建本地文件，它就会一步步帮你把这套知识库建好并验证。
>
> **整个过程默认只在本地创建文件。** Git、GitHub 和多设备同步不会自动开启。

## 使用步骤

1. 打开你的 AI 助手；
2. 复制下方代码块全部内容（含「开始」「结束」两行）；
3. 粘贴给它，并允许它检查电脑环境和创建本地文件；
4. 它问你知识库名称和保存位置时，告诉它你的选择（**一次回答一个问题**）；
5. 遇到系统权限、登录、安全确认时，**由你本人接管**；
6. 它完成后会给出验证结果，你自己核对一遍再开始用。

## 你只需要准备两个答案

- **知识库名称**：例如「张三的知识库」
- **保存位置**：例如「文档」目录下的一个新文件夹

没想好也没关系，AI 会先给一个安全建议，但它**不能替你覆盖任何已有目录**。

【开始：个人知识库自动构建任务】

你的任务是在我的电脑上确认或安装 Obsidian，并从零创建一套新的个人知识库。

这不是咨询任务。确认必要信息后请实际执行：检查环境、安装应用、创建目录和 Markdown 文件、验证结果，并把知识库打开给我使用。

一、最终目标

完成后我应该得到：
1. 一个可以正常启动的 Obsidian；
2. 一个位于我指定目录的新知识库；
3. 一套包含「个人、工作经历、复盘与规划」三个主板块的目录；
4. README、使用说明、AGENTS.md、行动总览、规划总览、项目索引、决策日志、主题手册索引、经验卡片索引、复盘入口、对话沉淀说明、以及日报/周复盘/月复盘/决策/经验卡片五个模板；
5. 少量明确标注为「脱敏示例」的虚构内容，帮助我理解怎么使用；
6. 一份实际验证结果，而不是只告诉我「理论上已完成」。

二、工作原则

1. 先读取环境再执行；不要让我重复提供你能安全检查到的信息。
2. 先确认目标目录不存在或为空；不得覆盖任何已有文件。
3. 优先使用 Obsidian 官方下载和官方安装方式。
4. 只创建本任务要求的内容，不安装无关插件，不增加复杂依赖。
5. 所有示例必须标注「脱敏示例，不代表真实项目」。
6. 不记录密码、令牌、验证码、Cookie、完整身份证件、银行卡或其他敏感信息。
7. 不创建公开仓库，不自动上传网络，不默认配置 GitHub。
8. 每个阶段完成后先检查结果，再进入下一阶段。
9. 能安全继续就直接执行；只有触发下方停止条件时才暂停询问。

三、必须暂停并让我处理的情况

出现以下任一情况时，停止当前操作，说明原因和我需要做的动作：
- 目标目录已存在文件，可能发生覆盖、合并或冲突；
- 需要输入管理员密码或确认系统权限；
- 需要登录、验证码、二维码、身份验证或付费；
- 需要创建 GitHub 账号、授权 GitHub、创建远程仓库或执行最终推送；
- 需要删除、覆盖、移动任何已有文件；
- 无法确认操作系统、CPU 架构、安装渠道或 Obsidian 是否已安装；
- 下载来源不是 Obsidian 官方网站或系统可信的软件渠道；
- 安装或目录验证失败，且重复检查后仍无法确认原因。

暂停时使用下面的状态格式：

状态：需要用户操作
原因：一句话说明为什么必须暂停
请你完成：列出唯一明确的下一步
完成后回复：告诉我应该回复什么内容

四、阶段 1：确认环境和创建位置

1. 检查当前操作系统是 macOS、Windows 还是 Linux。
2. 检查 Obsidian 是否已经安装。
3. 如果我还没提供知识库名称和目标目录，一次只问我一个问题：先问名称，再问保存位置。
4. 将最终路径完整显示给我确认。
5. 检查目标路径：不存在则创建；存在且为空则使用；存在且包含任何文件则必须暂停，不得覆盖。

五、阶段 2：检测或安装 Obsidian

先检测是否已安装；已安装且能启动时跳过下载。

未安装则打开官方下载页：https://obsidian.md/download

按系统选择官方支持方式：
- macOS：下载 Universal 安装包，打开后将 Obsidian 放入 Applications；遇到系统安全确认或权限弹窗时让我接管。
- Windows：下载 Windows Universal 安装程序，打开并按安装向导执行；遇到管理员权限或安全确认时让我接管。
- Linux：按当前发行版和已有包管理方式，在官方 AppImage、Snap、Deb 中选择；Flatpak 属社区维护方案，只有我明确同意时才用。执行需要管理员权限的命令前必须暂停说明。

安装后必须进行至少一项实际验证：应用可以启动，或系统应用目录中存在 Obsidian 且能读到版本信息。

下载完成 ≠ 安装完成；安装完成 ≠ 应用可以启动。不要混用这些状态。

- `app.json`：`{"attachmentFolderPath": "02-工作经历/07_附件", "alwaysUpdateLinks": true, "useMarkdownLinks": false, "newLinkFormat": "shortest"}`

七、阶段 4：写入核心入口文件

可以润色说明文字，但不能改变每个文件的职责。

1. README.md
必须包含：
- 知识库名称；
- 一句话定位：「这不是资料收藏夹，而是连接规划、行动、证据、复盘和经验的个人工作系统」；
- 三个问题入口：现在要做什么 → 行动总览；为什么要做 → 规划总览；做完后如何复盘 → 复盘与规划；
- 三个主板块的用途；
- 三条原则：当前状态只有一个入口、没有证据不宣称完成、原始资料和提炼结论分开。

2. 使用说明.md
必须告诉用户第一次使用时：先在规划总览写未来三个月最重要的方向；再在行动总览写本周三个具体动作；每天下班前记录事实、证据、判断和下一步；每周根据日报做复盘；连续使用四周后再增加目录和自动化。

3. 行动总览.md（最重要，写细一些）
必须声明「这是跨天行动当前状态的唯一入口」，并包含：
- 五类编号规则：A-nnn 下一步行动（自己能直接开始）／W-nnn 等待（依赖别人·数据·审核）／J-nnn 需要判断（只有用户能补充或选择）／H-nnn 暂缓（有价值但当前不承诺）／E-nnn 历史遗留（旧记录未完成、状态无法确认）。编号只增不重用。
- 十字段：编号、下一步动作、状态、状态原因、来源、归属、硬截止、建议复核、完成定义、完成证据。
- 八种状态：未开始、进行中、等待、待判断、暂缓、状态不明、已完成、已取消。
- 一张十列的行动表，加三条脱敏示例（一条 A、一条 W、一条 J），明确标注为示例、可由用户删除。
- 一段说明：完成分四层（已提交／已上线／已验收／已见效果），前一阶段不代表后一阶段。

4. 规划总览.md
建立人生、职业、学习、生活、个人项目五类规划入口。每项规划包含：目标、完成定义、时间范围、不做什么、关联行动编号、状态、复盘时间。必须写明：没有下一步动作的规划只能算「待判断」或「参考」，不算生效。

5. 项目索引.md
字段包括：项目名称、目标、当前阶段、最近进展（带日期）、待验证结果、下一步、项目入口、关联行动编号。加入一个「产品 A 激活率优化」的脱敏示例。必须声明：这里只记项目阶段，不维护第二套行动状态。

6. 决策日志.md
说明一条决策必须记录：背景、备选方案、最终决定、当时约束、放弃原因、原本预期、实际结果、验证状态和来源。强调「只有结论没有过程的决策等于没记」。加入一个「首版只改关键流程」的脱敏示例。

7. 主题手册索引.md
说明主题手册用于保存跨项目都成立的成套方法（如需求判断、验证与测试、数据分析、AI 协作）。写明开手册的三个条件：至少两个项目遇到、已形成稳定步骤、下次能照着做。没有真实内容时只保留说明，不创建空手册。

8. 经验卡片索引.md
说明一张卡只记一条经验，必须包含：结论、适用条件、推荐做法、限制或反例、来源、状态。加入三条脱敏示例，其中一条必须是「把上线、验收和效果分开记录」。

9. 复盘与规划.md
链接日报、周复盘、月复盘、季复盘、年复盘和下一阶段规划。说明各层级都从更细一级的事实和证据提炼，不能凭记忆补写；并区分实施证据、效果证据、陈述证据，三者不能互相替代。

10. 对话沉淀说明.md
说明 AI 对话只沉淀有长期价值的需求、决定、修正、经验和方法；不复制工具日志、密码、令牌或整段聊天。内容按项目或主题更新，不按日期每天新建摘要。列出一条条目必须包含的字段：条目 ID、类型、结论、来源平台、来源对话、对话日期、状态。

九、阶段 6：生成 AGENTS.md

AGENTS.md 是给后续 AI 助手阅读的操作规则，至少包含：

# 知识库 AI 操作规则

## 目标
帮助用户找回上下文、维护行动、保留证据、完成复盘和沉淀经验；不代笔，不替用户做判断。

## 唯一事实源
行动总览是跨天任务当前状态的唯一入口；日报、项目笔记、规划页只引用，不各写一份状态。

## 写入分流
跨天跟进 → 行动总览；方向与规划 → 规划总览或个人目录；项目背景 → 项目索引；有取舍的判断 → 决策日志；可复用结论 → 经验卡片；成套方法 → 主题手册；当天事实 → 每日记录；周期结论 → 对应复盘目录；AI 对话结论 → 对话沉淀。

## 原始层只读
02-工作经历/04_日报素材/、05_文档原文/、07_附件/ 只读不写；要提炼就把结论写到提炼层。

## 行动体系
五类编号 A/W/J/H/E；十字段；八种状态；完成分四层，没有证据不许打勾。

## 维护规则
写入前先查重；区分事实、判断、行动、待确认；保留来源与适用条件；双链用完整相对路径且不带 .md 后缀；库中无对应笔记时提醒用户是否新建，不要写空链接；不反推历史想法；只做最小修改；删除已有文件或大段内容前必须询问。

## 必须询问
删除覆盖移动；大范围改目录；改变已确认判断；缺少来源要写结论；配置 Git 或外部同步；涉及账号身份支付证件。

## 禁止写入
密码、令牌、Cookie、验证码、私钥、完整身份证号、银行卡号；没有来源却伪装成事实的内容；为补齐格式而编造的历史记录。

## 完成前检查
文件位置正确；无重复条目；入口页能找到新内容；双链指向真实存在的文件；无敏感信息；没改原始层；完成状态有证据；本机界面状态（.obsidian/workspace.json）未暂存。

十、阶段 7：验证

创建完成后进行实际检查：
1. 列出所有核心目录和文件，逐项对照本指令；
2. 检查 README 中的三个入口都能找到目标文件；
3. 检查所有双链的完整相对路径都对应一个真实存在的 Markdown 文件；
4. 检查脱敏示例都带有「脱敏示例」说明；
5. 搜索密码、令牌、验证码、私钥等敏感字段，确认没有真实值；
6. 确认目标目录之外没有新增或修改文件；
7. 确认 Obsidian 已安装且能够启动；
8. 用 Obsidian 打开新建目录，确认它被识别为知识库；
9. 任何检查失败，先修复并重新检查，不能直接宣称完成。

十一、交接方式

最终只使用下面三种状态之一：

状态：已完成
- Obsidian：说明检测、安装和启动证据
- 知识库位置：显示完整路径
- 已创建：列出三个主板块和核心入口
- 验证结果：列出通过项和数量
- 从这里开始：README → 使用说明 → 规划总览 → 行动总览

状态：需要用户操作
- 原因：说明权限、登录、目录冲突或其他阻塞
- 请你完成：只给一个明确动作
- 完成后回复：告诉我应该回复什么

状态：未完成
- 已完成部分：如实列出
- 失败位置：说明哪个阶段失败
- 证据：给出错误信息或验证结果
- 安全状态：说明是否修改了任何文件，以及如何恢复

不要把「已下载」写成「已安装」，不要把「已创建文件」写成「已验证可用」，不要把「已初始化 Git」写成「已同步 GitHub」。

现在开始执行阶段 1。先检查环境；如果缺少知识库名称或保存位置，再一次只问我一个问题。

【结束：个人知识库自动构建任务】

## 建好之后怎么用

不要先批量导入旧资料。先完成三件事：

1. 在 `规划总览.md` 写下未来三个月最重要的**一个**方向；
2. 在 `行动总览.md` 写下本周能推进它的**三个**行动；
3. 连续一周，每天记录**事实、证据、判断、下一步**。

等这条最小闭环跑顺，再考虑 GitHub、多设备同步、历史资料导入和每日 AI 自动沉淀。

建好之后，把 [AGENTS](../AGENTS.md) 指给你的 AI 助手，告诉它「按这个规则维护我的知识库」。
之后你说「帮我记一下 X」，它会自动判断该写到哪里、需要问你什么。
