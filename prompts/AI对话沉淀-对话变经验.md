# 任务：把 AI 对话沉淀成知识库条目

> **这是什么**：一段可选进阶提示词，**面向能读写知识库目录的 AI 助手**（WorkBuddy / Codex / Cursor / Claude Code 等）。把一段或多段 AI 对话，提炼成库里可检索、可复用的沉淀条目——解决「跟 AI 聊一晚，第二天开新对话它全忘了」。
>
> **配套方法论**：落点规则与仓库内 `03-复盘与规划/07-对话沉淀/对话沉淀说明.md` 完全一致；两者一起用，提示词负责执行，说明负责口径。
>
> **依赖说明**：AI 需要能读写你的知识库目录（沉淀条目的落点）。纯网页版对话窗口没有文件读写能力，只能帮你「提炼文字」，落库要手动。
>
> 来源：王树辉私有环境工作流（2026-10），整理入本模板时仅补充依赖说明，流程与口径原样保留。

## 输入参数

- 对话内容：{{粘贴对话全文，或给出对话导出文件/目录路径}}
- 来源平台：{{哪个 AI 工具，如 WorkBuddy / Codex / ChatGPT}}
- 对话日期：{{具体日期或范围}}
- 落点目录：{{默认 `03-复盘与规划/07-对话沉淀/` 下按项目或主题分子目录；不确定就问，不要猜}}

## 第一步：筛掉过程垃圾

只沉淀这五类，逐条对号入座：

| 类型 | 例子 |
|---|---|
| 需求 | 「我要的不是 A，而是 B」这类澄清 |
| 决定 | 你明确拍板了的选择 |
| 修正 | 你纠正了 AI、或它纠正了你的地方 |
| 经验 | 形成了一条以后能复用的结论 |
| 方法 | 形成了一套能照着做的步骤 |

**不沉淀**：工具日志、报错堆栈、`git` 输出；验证码、密码、令牌、Cookie、私钥、完整身份证号、银行卡号；整段聊天记录（复制粘贴不是沉淀）；情绪吐槽和礼貌性客套。

## 第二步：逐条提炼

每条沉淀条目必须包含这些字段：

```text
条目 ID       WB-001 / CE-001 这样的稳定编号（续编，不重用）
类型          需求 / 决定 / 修正 / 经验 / 方法
结论          一句话，能被别人复述
来源平台      哪个 AI 工具
来源对话      哪次对话（能回查）
对话日期      具体日期
状态          有效 / 待验证 / 已失效
```

## 第三步：写前查重

1. 先在库内搜索同结论的已有条目——有，就**追加一个来源**，不新建第二条。
2. 同一主题有了新结论，**追加到已有条目**，不要新建第二篇。
3. 「今天和 AI 聊了什么」这种按天堆的摘要，三个月后没有任何检索价值——**按项目或主题组织，不按日期新建**。

## 第四步：落地与收尾

1. 把条目写进落点目录，格式对齐库内已有条目。
2. **每次沉淀后更新对应索引**——沉淀了但找不到，等于没沉淀。
3. 读完一次对话**没有新结论，也要标记为「已处理」，但不要创建空文件**——空文件比没有更糟。
4. 正文汇报：沉淀了几条、各是什么类型、落到哪个文件；无新结论也要明说「本次无新结论，已标记」。
5. **AI 的总结不等于你的结论**：沉淀的是你认可的判断，不是 AI 生成的文字。分不清是不是用户拍板的，标「待验证」，不要写成「有效」。

## 硬性约束

- 不猜对话里没有的信息；空结果或失败不能被总结成「没做这件事」，需注明「本次未命中」。
- 敏感信息（凭证、证件号）一律不入库。
- 一次最多处理 5 个对话，处理完跑一遍体检再进下一批。
- 批量回溯时，会话 ID 从工具自身的会话标识取，不要用日志文件名去重——文件名会变，会话不会。
