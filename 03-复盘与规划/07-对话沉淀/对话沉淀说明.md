# 对话沉淀说明

> 和 AI 的对话里，90% 是过程垃圾，10% 是长期资产。
> **这一页只管那 10%。**

## 什么值得沉淀

只有这五类：

| 类型 | 例子 |
|---|---|
| 需求 | "我要的不是 A，而是 B" 这类澄清 |
| 决定 | 你明确拍板了的选择 |
| 修正 | 你纠正了 AI 或它纠正了你的地方 |
| 经验 | 形成了一条以后能复用的结论 |
| 方法 | 形成了一套能照着做的步骤 |

## 什么不沉淀

- 工具日志、报错堆栈、`git` 输出；
- 密码、令牌、验证码、Cookie、私钥、完整身份证号、银行卡号；
- 整段聊天记录（复制粘贴不是沉淀）；
- 情绪吐槽和礼貌性客套。

## 怎么组织

**按项目或主题更新，不按日期每天新建一篇摘要。**

```text
07-对话沉淀/
├── 00-总索引/        （条目多了再建：总索引、按项目检索、按主题检索）
├── 01-工作项目/
├── 02-个人项目/
└── 03-通用主题/
```

同一主题有了新结论，就**追加到已有条目**，不要新建第二篇。
"今天和 AI 聊了什么"这种按天堆的摘要，三个月后没有任何检索价值。

## 一条沉淀条目必须包含

```text
条目 ID       WB-001 / CE-001 这样的稳定编号
类型          需求 / 决定 / 修正 / 经验 / 方法
结论          一句话，能被别人复述
来源平台      哪个 AI 工具
来源对话      哪次对话（能回查）
对话日期      具体日期
状态          有效 / 待验证 / 已失效
```

## 铁律

1. **写前全库查重。** 同结论已有条目，就追加一个来源，不新建。
2. **读完一次对话没有新结论，也要标记为"已处理"，但不要创建空文件。** 空文件比没有更糟。
3. **每次沉淀后更新对应索引。** 沉淀了但找不到，等于没沉淀。
4. **AI 的总结不等于你的结论。** 沉淀的是**你认可的判断**，不是 AI 生成的文字。

## 批量回溯时注意

- 会话 ID 要从工具自身的会话标识取，**不要用日志文件名去重**——文件名会变，会话不会；
- 上下文回放（比如系统把历史消息重放一遍）**不算新的用户原话**；
- 一次最多处理 5 个会话，处理完跑一遍体检再进下一批。
