# 个人知识库开源模板

[![License: MIT](https://img.shields.io/badge/License-MIT-brightgreen.svg)](LICENSE)
[![GitHub stars](https://img.shields.io/github/stars/wangshuhui0613/personal-kb-template?style=flat)](https://github.com/wangshuhui0613/personal-kb-template/stargazers)
[![健康检查](https://github.com/wangshuhui0613/personal-kb-template/actions/workflows/health-check.yml/badge.svg)](https://github.com/wangshuhui0613/personal-kb-template/actions/workflows/health-check.yml)
[![在线演示](https://img.shields.io/badge/演示-在线预览-blue)](https://wangshuhui0613.github.io/personal-kb-template/)

一套用于管理**规划、行动、证据、复盘和经验**的个人知识库结构。

它不是收藏夹。收藏夹解决的是“存”，这套模板解决的是“**用**”——让半年后的你还能回答出：当时为什么这么决定。

这套方法有个名字，叫**行动账本（Action Ledger）**：知识库按账本管——一个状态入口、五类科目、四层入账进度、三类凭证。展开见下文「几个关键设计」。

![新用户第一天：clone → 打开 → 写日报 → 体检](docs/demo.gif)

## 它回答四个问题

| 问题 | 从哪里找答案 |
|---|---|
| 我现在应该做什么？ | [行动总览](01-个人/00-行动与跟进/行动总览.md) |
| 我以前做过什么，当时为什么这样判断？ | [项目索引](02-工作经历/00_总览/项目索引.md)、[决策日志](02-工作经历/01_决策日志/决策日志.md) |
| 哪些经验以后可以直接复用？ | [经验卡片索引](02-工作经历/03_经验卡片/经验卡片索引.md) |
| 我现在处在什么阶段，下一步去哪？ | [复盘与规划](03-复盘与规划/复盘与规划.md) |

让这四个问题转起来的是一条闭环：

```text
规划 → 行动 → 证据 → 复盘 → 经验 → 调整规划与行动
```

## 快速开始

**要求**：本地有 [Obsidian](https://obsidian.md)（免费）。不需要任何社区插件，原生功能即可运行。

### 方式一：clone 下来直接用

```bash
git clone https://github.com/wangshuhui0613/personal-kb-template.git 我的知识库
```

用 Obsidian「打开文件夹作为库」选中它。模板、日记、附件路径**已经配好**，开箱即用：

- `Ctrl/Cmd + P` → 输入「插入模板」→ 选「日报模板 / 决策模板 / 经验卡片模板」
- 点左侧日历图标，自动在 `03-复盘与规划/01-每日记录/` 建好当天的日记
- 粘贴的图片自动进 `02-工作经历/07_附件/`

然后做三件事：

1. 在 `01-个人/规划总览.md` 写下未来三个月最重要的**一个**方向
2. 在 `01-个人/00-行动与跟进/行动总览.md` 写下本周能推进它的**三个**行动
3. 删掉里面所有标注为示例的内容

> 更多上手细节见 [使用说明](使用说明.md)。

### 方式二：装成 Agent Skill，让 AI 帮你建和维护

最快一条命令（需要 Node.js）：

```bash
npx skills add wangshuhui0613/personal-kb-template
```

`skills` 是 Agent Skills 生态的标准安装命令，支持 Claude Code、Codex、Cursor 等 75+ 个 Agent。

不想用 npx，也可以把 `skills/personal-kb/` 整个目录复制到你的 Agent 的 skills 目录：

| 平台 | 项目级 | 全局 |
|---|---|---|
| Claude Code | `.claude/skills/` | `~/.claude/skills/` |
| Cursor | `.cursor/skills/` | `~/.cursor/skills/` |
| Codex | `.codex/skills/` | `~/.codex/skills/` |
| GitHub Copilot | `.github/skills/` | `~/.copilot/skills/` |

之后直接说「帮我搭个知识库」，或日常说「帮我记一下这件事」。

### 方式三：不想装 Skill，只复制一段指令

打开 [一键构建](prompts/一键构建.md)，把里面从「开始」到「结束」的整段复制给你的 AI 助手，它会一步步帮你把库建好并给出验证结果。

## 第一天，只做三件事

无论你选了哪种方式，第一天只做这三件事，各花五分钟：

1. **写下今天的第一篇日报。** Obsidian 里点左侧日历图标，或直接对 AI 说「帮我记一下今天做了什么」。今天真实发生的事，是这个库唯一不能伪造的原料。
2. **把脑子里最挂着的那件事，写进行动总览。** 给它一个编号（`A-001`），写清下一步动作。从这一秒起，它有了被跟踪的资格。
3. **跑一次体检。** `python tools/vault_health_check.py --root .`（Windows 也可以双击 `tools/health-check.cmd`），确认结构完好。

做完这三件，这个库就开始为你产出了。一周之后，再回来读「日常怎么用」。

## 日常怎么用

只需要回答三个问题：

```text
今天真正发生了什么？
它改变了我哪个判断？
下一步最小行动是什么？
```

第一个喂给日报，第二个喂给复盘，第三个喂给行动总览。

| 你想记的是 | 写到哪 |
|---|---|
| 需要跨天跟进的事 | [行动总览](01-个人/00-行动与跟进/行动总览.md) |
| 方向、规划 | [规划总览](01-个人/规划总览.md) 或 `01-个人/` 对应子目录 |
| 项目整体背景 | [项目索引](02-工作经历/00_总览/项目索引.md) |
| 一次有取舍的选择 | `02-工作经历/01_决策日志/` |
| 一个能复用的结论 | `02-工作经历/03_经验卡片/` |
| 今天真实发生的事 | `03-复盘与规划/01-每日记录/` |
| 周 / 月 / 季 / 年结论 | `03-复盘与规划/` 对应目录 |

**节奏**：每天下班前五分钟写日报；周末从本周日报提炼周复盘；月末从周复盘提炼月复盘。每一层只能从下一级提炼，**不要凭记忆重写**。

## 谁适合用

同一个结构，不同人的用法：

- **开发者 / 技术负责人**：决策日志记技术选型「当时只有哪些信息、放弃了什么」；经验卡片存踩坑结论和成立条件；用 Skill 让 AI 按同一套规范建库、记日报。
- **产品经理 / 项目负责人**：项目索引管各项目阶段；行动总览管跨天跟进，`W`（在等别人）和 `J`（等你拍板）分开列；三类证据分开写——实施记录、业务数据、他人陈述不能互相顶替。
- **学生 / 研究者**：日报攒过程证据，主题手册把方法沉淀成「什么条件下成立」，规划总览管长期目标，周复盘只从本周日报提炼。

共同点：都在回答同一个问题——**三个月后的我，还能不能复原今天的判断？**

## 几个关键设计

这套方法叫**行动账本**，因为每个设计都对应记账的一个动作：

| 记账概念 | 对应设计 |
|---|---|
| 一本总账 | ① 当前状态只有一个入口 |
| 科目 | ② 五类行动编号 A / W / J / H / E |
| 入账进度 | ③ 完成分四层 |
| 凭证 | ④ 决策记约束、经验记边界；完成证据单独存档 |
| 原始凭证不涂改 | ⑤ 原始层只读 |

这些是这套模板和普通文件夹结构的区别，建议先读一遍再用：

**① 当前状态只有一个入口。**
一条行动「现在怎么样了」只写在行动总览，其他地方一律用链接引用。两份状态副本，一周内必然打架。

**② 行动有编号和字段。**
前缀区分性质：`A` 自己能动手、`W` 在等别人、`J` 等你拍板、`H` 暂缓、`E` 历史遗留。每条要写清下一步动作、状态、状态原因、来源、归属、截止、复核时间、完成定义、完成证据。完整字段说明见 [行动总览](01-个人/00-行动与跟进/行动总览.md)。

**③ 完成分四层。**

```text
已提交 ≠ 已上线 ≠ 已验收 ≠ 已见效果
```

不要合并写成「已完成」。关闭一条行动时，要写清到了哪一层并附上日期和证据。

**④ 决策记约束，经验记边界。**
决策写「当时只有这些信息、放弃了什么、为什么放弃」——没有过程的决策，半年后没法复用。经验写「什么条件下成立、什么情况下不成立」——没有边界的方法迟早被用错地方。

**⑤ 原始层只读。**
`04_日报素材`、`05_文档原文`、`07_附件` 是事实之源，不改写。要提炼就把结论写到上层去，否则上层所有结论的出处都会断掉，而且你不会发现。

完整规则见 [AGENTS](AGENTS.md)。

## 体检

```bash
python tools/vault_health_check.py --root .
```

Windows 用户也可以直接双击 `tools/health-check.cmd`。

检查入口文件是否齐全、链接有没有断、行动表的字段和状态是否合法。**只读不写**，退出码 1 表示有问题。

## 在线预览

- `docs/index.html` —— 离线自包含，双击就能在浏览器打开
- `docs/index-cdn.html` —— 引了网络字体和动效，效果更丰富

方向键翻页，空格下一页，右下角有自动播放。

## 只想要纯粹的 Obsidian 库？

仓库里除了三个 `0x-` 板块，其余（`prompts/`、`skills/`、`tools/`、`docs/`、根目录几个 `.md`）都是给 AI 和展示用的。如果你只想要干净的笔记库，clone 之后跑一行：

```bash
rm -rf prompts skills tools docs .github CONTRIBUTING.md AGENTS.md
```

保留 README、使用说明、LICENSE 和三个板块即可。
