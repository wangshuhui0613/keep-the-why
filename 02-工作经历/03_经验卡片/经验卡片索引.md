# 经验卡片索引

> **一张卡只记一条经验。** 写不下说明该拆成两张，或者该升级成主题手册。
>
> 用 [经验卡片模板](../../03-复盘与规划/99-模板/经验卡片模板.md)。

## 一条经验必须写全

| 字段 | 为什么不能省 |
|---|---|
| 结论 | 一句话，能被别人复述 |
| 适用条件 | **最关键**。离开条件，结论就是错的 |
| 推荐做法 | 具体怎么做，能照着执行 |
| 限制或反例 | 什么情况下这条不成立 |
| 来源 | 从哪个项目、哪次复盘来的 |
| 状态 | `有效` / `待验证` / `已失效` |

## 铁律

- **写前先查重。** 同主题的结论已有，就追加来源，不要新建第二张卡。换汤不换药的重复卡片，是知识库腐化的起点。
- **不写"正确的话"，只写"我验证过的话"。** "沟通很重要"不是经验，"上线前把验收清单发给三方确认，能把返工率明显降低"才是。
- **失效了就标 `已失效` 并写原因，不要删。** 一条失效的经验，比十条有效的更能说明边界。

## 卡片列表

> 下面是**脱敏示例，不代表真实项目**。看懂格式后整段删掉。

### EXP-001｜把上线、验收和效果分开记录

- **结论**：技术上线只证明版本可用，不证明用户问题已经解决
- **适用条件**：产品改版、活动、增长实验、自动化任务
- **推荐做法**：分别记录三类证据 —— 上线证据（版本号与日期）、验收证据（谁确认的、清单覆盖哪些）、业务指标（观察窗口前后的数值）
- **限制或反例**：纯技术重构且不影响用户路径时，可以只记上线与回归结果
- **来源**：产品 A 新手引导改版复盘
- **状态**：有效

### EXP-002｜先定"每天哪个时段做"，再定"做多少"

- **结论**：学习计划失败通常不是因为目标太高，而是因为没有落到具体时段
- **适用条件**：任何需要长期坚持、但缺乏外部截止的个人计划
- **推荐做法**：先把时段写进日历，再谈每周多少次；跑两周再评估强度
- **限制或反例**：有外部硬性截止的任务（考试、交付）不受此限，倒排工期更有效
- **来源**：个人学习计划作废复盘
- **状态**：有效

### EXP-003｜让 AI 从原始语料提炼，而不是让它凭空总结

- **结论**：AI 凭记忆写的周报，会把上周的事写成本周的
- **适用条件**：任何要求 AI "总结这段时间"的场景
- **推荐做法**：先把原始记录喂给它，要求逐条对应；再让它标注哪些条目找不到对应证据
- **限制或反例**：纯观点性写作不需要原始语料，硬喂反而限制发挥
- **来源**：多次周报复盘
- **状态**：有效

### EXP-004｜比率类指标先问「分母是谁」

- **结论**：看到任何比率（转化率、完成率、增长率），先确认分母的定义，再看数字大小。
- **适用条件**：看板、报表、竞品对比里引用的所有比率类指标。
- **推荐做法**：把分母口径写进 `02-工作经历/06_数据/` 对应文件（如 [注册转化率](../06_数据/注册转化率.md)）；引用比率时带口径链接。
- **限制或反例**：绝对量（DAU、订单数）不适用；双方已确认口径的长期指标不必每次重问。
- **来源**：2026-10-15 产品 A 注册转化率修正事件（见 [2026-10-15 日报](../../03-复盘与规划/01-每日记录/2026-10-15.md)）
- **状态**：有效
