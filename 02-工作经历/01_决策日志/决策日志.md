# 决策日志

> 决策记的是"**在信息不全的时候，我选了什么、放弃了什么**"。
>
> 它和经验的区别只有一条：经验是"事后学到了什么"，决策是"当时只能这么选"。
> **只有结论没有过程的决策，等于没记——因为约束一变，这个判断就不能复用。**

## 一条决策必须写全

用 [[03-复盘与规划/99-模板/决策模板]]，一条都不能省：

| 字段 | 为什么不能省 |
|---|---|
| 背景 | 没有背景，半年后你不知道在解决什么问题 |
| 备选方案 | 只写最终方案，等于没记——决策的本质是取舍 |
| 最终决定 | 一句话说清选了哪个 |
| 当时约束 | **最关键**。资源、时间、数据、人，哪些限制了这个选择 |
| 放弃原因 | 为什么另外几个不行。这是最容易被跳过、也最值钱的一栏 |
| 原本预期 | 当初以为会发生什么 |
| 实际结果 | 后来真的发生了什么 |
| 验证状态 | `待验证` / `已验证` / `已被推翻` |
| 来源 | 哪次会议、哪次对话、哪份数据 |

## 三条铁律

1. **不许根据结果反推当时的想法。** 结果好就写"我当时预判很准"，那是自传不是档案。
2. **约束变了就要重新判断，不要照抄旧结论。** 所以约束必须写下来。
3. **被推翻的决策不要删。** 一条被推翻的决策，比十条"验证通过"的更能告诉你边界在哪。

## 决策列表

> 下面是**脱敏示例，不代表真实项目**。看懂格式后整段删掉。

### DEC-001｜首版只改关键流程，不做全页面改版

- **背景**：产品 A 新手引导流失偏高，但原因不清楚，数据还没定位到具体步骤
- **备选方案**：① 全页面改版 ② 只改关键流程 ③ 先不动，只补数据埋点
- **最终决定**：只改关键流程
- **当时约束**：开发资源只有一个前端两周；主要流失点尚未被数据确认
- **放弃原因**：
  - 全页面改版：成本高，而且同时改多处会导致"到底是哪处起了作用"永远说不清
  - 先不动：业务方不接受再等一个迭代
- **原本预期**：关键流程完成率提升，且能定位到主要流失步骤
- **实际结果**：首版按期上线，内部验收通过；业务效果待两周数据验证
- **验证状态**：待验证
- **来源**：产品 A 改版评审（2026-09-28）
- **关联行动**：`A-001`

### DEC-002｜暂时不接第三方登录

- **背景**：产品 B 商家后台有商家反馈希望支持第三方登录
- **备选方案**：① 本期接入 ② 本期只做账号密码 + 后续评估
- **最终决定**：本期只做账号密码
- **当时约束**：账号体系还没定，接入第三方会先锁死用户模型
- **放弃原因**：一旦用户模型绑定第三方 ID，后面改成本极高；当前商家规模也不足以证明需求真实
- **原本预期**：少数商家抱怨，但不影响整体转化
- **实际结果**：**尚未验证** —— 上线时间未定
- **验证状态**：待验证
- **来源**：产品 B 需求评审（2026-09-15）
