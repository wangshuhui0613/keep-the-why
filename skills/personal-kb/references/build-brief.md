# 核心入口文件内容合同

建库时按这份合同写 10 个入口文件。**可以润色措辞，不能改变每个文件的职责。**
完整规则见同目录的 `rules.md`。

---

## 1. README.md

必须包含：

- 一句话定位：「这不是资料收藏夹，而是连接规划、行动、证据、复盘和经验的个人工作系统」
- 三个问题入口：现在要做什么 → 行动总览；为什么要做 → 规划总览；做完后如何复盘 → 复盘与规划
- 三个主板块的用途
- 三条原则：当前状态只有一个入口、没有证据不宣称完成、原始资料和提炼结论分开

## 2. 使用说明.md

必须告诉用户第一次使用时：

1. 先在规划总览写未来三个月最重要的**一个**方向
2. 再在行动总览写本周能推进它的**三个**行动
3. 每天下班前记录事实、证据、判断、下一步
4. 每周根据日报做复盘
5. 连续使用四周后再增加目录和自动化

## 3. 行动总览.md（最重要，写细）

必须声明「这是跨天行动当前状态的唯一入口」，并包含：

- **五类编号**（只增不重用）：
  | 前缀 | 含义 |
  |---|---|
  | `A-nnn` | 下一步行动（自己能直接开始） |
  | `W-nnn` | 等待（依赖别人、数据或审核） |
  | `J-nnn` | 需要判断（只有用户能补充或选择） |
  | `H-nnn` | 暂缓（有价值但当前不承诺） |
  | `E-nnn` | 历史遗留（旧记录未完成、状态无法确认） |
- **十字段**：编号、下一步动作、状态、状态原因、来源、归属、硬截止、建议复核、完成定义、完成证据
- **八种状态**：未开始、进行中、等待、待判断、暂缓、状态不明、已完成、已取消
- 一张十列的行动表，加三条脱敏示例（一条 A、一条 W、一条 J），全部标注「脱敏示例，不代表真实项目」
- 说明完成分四层：已提交 / 已上线 / 已验收 / 已见效果，前一阶段不代表后一阶段

## 4. 规划总览.md

建立人生、职业、学习、生活、个人项目五类规划入口。每项规划包含：
目标、完成定义、时间范围、**不做什么**、关联行动编号、状态、复盘时间。

必须写明：没有下一步动作的规划只能是「待判断」或「参考」，**不算生效**。

## 5. 项目索引.md

字段：项目名称、目标、当前阶段、最近进展（带日期）、待验证结果、下一步、项目入口、关联行动编号。

加入一个「产品 A 激活率优化」的脱敏示例。
必须声明：这里只记**项目阶段**，不维护第二套行动状态。

## 6. 决策日志.md

一条决策必须记录：背景、备选方案、最终决定、**当时约束**、**放弃原因**、原本预期、实际结果、验证状态、来源。

强调：只有结论没有过程的决策等于没记——约束一变，这个判断就不能复用。
加入一个「首版只改关键流程」的脱敏示例。

## 7. 主题手册索引.md

说明主题手册装的是跨项目都成立的**成套方法**（需求判断、验证与测试、数据分析、AI 协作）。

开手册的三个条件：至少两个项目遇到过、已形成稳定步骤、下次能照着做。
**没有真实内容时只保留说明，不创建空手册。**

## 8. 经验卡片索引.md

一张卡只记一条经验，字段：结论、**适用条件**、推荐做法、限制或反例、来源、状态（有效 / 待验证 / 已失效）。

加三条脱敏示例，其中一条必须是「把上线、验收和效果分开记录」。

## 9. 复盘与规划.md

链接日报、周复盘、月复盘、季复盘、年复盘和下一阶段规划。
说明各层级都从更细一级的事实提炼，**不能凭记忆补写**。
区分三类证据：实施证据、效果证据、陈述证据，三者不能互相替代。

## 10. 对话沉淀说明.md

只沉淀五类：需求、决定、修正、经验、方法。
不沉淀：工具日志、密码令牌、整段聊天、情绪吐槽。
按项目或主题更新，**不按日期每天新建摘要**。
条目字段：条目 ID、类型、结论、来源平台、来源对话、对话日期、状态。

| `周复盘模板.md` | `03-复盘与规划/99-模板/` |
| `月复盘模板.md` | `03-复盘与规划/99-模板/` |
| `决策模板.md` | `03-复盘与规划/99-模板/` |
| `经验卡片模板.md` | `03-复盘与规划/99-模板/` |

模板统一收口在 `03-复盘与规划/99-模板/`；`01-每日记录/` 只放每天生成的日记，不放模板文件。

## Obsidian 开箱配置

`.obsidian/` 四个文件必须创建（缺了它用户每次开新库都要手动配模板和日记）：

| 文件 | 内容 |
|---|---|
| `app.json` | `{"attachmentFolderPath": "02-工作经历/07_附件", "alwaysUpdateLinks": true, "useMarkdownLinks": false, "newLinkFormat": "shortest"}` |
| `core-plugins.json` | 核心插件 JSON 对象，`"templates": true` 与 `"daily-notes": true` 必须为 true |
| `templates.json` | `{"folder": "03-复盘与规划/99-模板"}` |
| `daily-notes.json` | `{"folder": "03-复盘与规划/01-每日记录", "format": "YYYY-MM-DD", "template": "03-复盘与规划/99-模板/日报模板.md"}` |

注意：`.obsidian/workspace.json` 属于本机界面状态，不写入、不入 Git。

## 验证清单

建完后逐项核对，任何一项失败就先修再报完成：

1. 所有必需目录和文件都在，且与 `assets/skeleton.txt` 一致
2. README 中的三个入口都能找到目标文件
3. 所有双链的**完整相对路径**都对应一个真实存在的 Markdown 文件
4. 示例内容都带有「示例」标注
5. 搜索密码、令牌、验证码、私钥等字段，确认没有真实值
6. 目标目录之外没有新增或修改文件
7. `.obsidian/` 四个文件存在，且 templates.json 与 daily-notes.json 指向的文件夹真实存在
8. Obsidian 已安装且能启动，打开新建目录被识别为知识库
