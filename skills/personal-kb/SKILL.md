# 个人知识库搭建与维护

## 这个技能交付什么

帮用户在本地建起一套**能长期用下去的个人知识库**，并且之后能持续维护它。

它不是资料收藏夹。核心是把四件事连成一条能回溯的链：

```text
规划 → 行动 → 证据 → 复盘 → 经验 → 调整规划与行动
```

建好之后，这套库要能稳定回答四个问题：我现在该做什么 / 我以前做过什么、当时为什么这么判断 / 哪些经验能直接复用 / 我下一步要去哪。

## 什么时候用

**用：** 从零搭建知识库；把一段话、一次对话、一天的工作记进已有知识库；写日报周报月报；把一次取舍记成决策；把一条教训沉淀成经验；检查知识库是否健康。

**不用：** 单纯的文件整理或格式转换；团队 wiki / 多人协作文档（那是另一个领域）；用户只是想找个地方存网页剪藏。

## 工作流程

### A. 从零搭建

1. **先问三件事，一次只问一个**：知识库名称、保存位置、你的角色（开发者 / 产品经理 / 学生研究者 / 其他）。角色只影响各板块侧重（见下文），不确定就记"其他"，不要猜。用户没想好名称和位置就给一个安全建议，**绝不覆盖已有目录**。
2. **检查目标路径**：不存在→创建；存在且为空→可用；存在且有文件→**停下问用户**。
3. **确认或安装 Obsidian**：只走官方渠道 <https://obsidian.md/download>。管理员密码、系统权限、登录、付费一律交回用户。
4. **建目录骨架**：读 `assets/skeleton.txt`，照它创建。不要为了让目录好看而多建空笔记。
5. **复制模板**：把 `assets/templates/` 里的五个模板放到对应位置。
6. **写 10 个核心入口文件**：严格按 `references/build-brief.md` 的内容合同写。可以润色措辞，**不能改变每个文件的职责**。
7. **生成 `AGENTS.md`**：把 `references/rules.md` 落到库根目录，这是给后续所有 AI 助手读的规则。
8. **验证**：逐项核对目录、检查所有链接指向真实存在的文件、确认示例都标了「脱敏示例」、扫描敏感字段。任何一项失败就先修再重报。

### B. 日常维护（库已存在时）

先读库里的 `AGENTS.md`；没有就先生成一份。然后按分流写入：

| 用户说的是 | 写到哪 |
|---|---|
| 帮我记一下 / 提醒我 / 这个要跟进 | `01-个人/00-行动与跟进/行动总览.md` |
| 人生、职业、学习、生活方向 | `01-个人/规划总览.md` 或对应子目录 |
| 一个项目的背景和状态 | `02-工作经历/00_总览/项目索引.md` |
| 有明确取舍的选择 | `02-工作经历/01_决策日志/` |
| 能复用的单条结论 | `02-工作经历/03_经验卡片/` |
| 成套的做事方法 | `02-工作经历/02_主题手册/` |
| 当天真实发生的事 | `03-复盘与规划/01-每日记录/` |
| 周 / 月 / 季 / 年结论 | `03-复盘与规划/` 对应目录 |
| AI 对话里的长期结论 | `03-复盘与规划/07-对话沉淀/` |

详细规则（字段、状态、编号、证据口径、禁止写入）全部在 `references/rules.md`，**每次写入前读一遍**。

### C. 老库迁移（/adopt）

用户已有一个 Obsidian 库，说「/adopt」「帮我迁移」「按这套结构整理旧库」时：

1. **确认旧库路径，整体视为只读素材**——不拆、不改、不重命名任何旧文件。
2. **扫描出现有结构**，列成「旧目录 → 建议对应板块」的表，和用户逐项确认；对不上号的放 `99_元信息/` 标「待归类」，不要硬塞。
3. **只挑跨天还在跟进的事**，和用户逐条确认后，按 A / W / J / H / E 分类进行动总览开编号。其余旧内容留在原处。
4. 旧库的日记、文档、附件原样对应到只读层（`04_日报素材/`、`05_文档原文/`、`07_附件/`）。
5. 迁移完成后写一条**迁移说明**：迁了什么、没迁什么、为什么。
6. **铁律：迁移是加一层，不是洗一遍。** 「把全部旧笔记重新归类」这种请求要先问清风险再做——洗库丢的是用户几年的上下文，比不整理危险得多。

## 按角色调整侧重

结构不变，各板块侧重按角色变。搭建时问清角色并写进 `AGENTS.md` 开头，以后每次写入都按这个侧重：

| 角色 | 决策日志侧重 | 经验卡片侧重 | 其他 |
|---|---|---|---|
| 开发者 / 技术负责人 | 技术选型：备选方案、当时约束、放弃原因 | 踩坑结论 + 成立条件 | 主题手册沉淀可复用的工程方法 |
| 产品经理 / 项目负责人 | 需求取舍：当时有哪些信息、放弃了什么 | 流程与协作方法 | 行动总览里 W（等别人）和 J（等你拍板）分开列；三类证据不互替 |
| 学生 / 研究者 | 方向选择：为什么选这个课题 / 路线 | 学习方法与工具结论 | 日报攒过程证据；规划管长期目标 |

角色只是起点，不是限制——用户明确说「我这块要按另一类写」时，听用户的。

## 三条最容易犯的错

| 症状 | 原因 | 怎么改 |
|---|---|---|
| 同一件事在两个地方状态不一样 | 在日报和项目笔记里各写了一份"现在怎么样了" | 当前状态只写在行动总览，别处用链接引用 |
| 半年后回看，不知道当时为什么这么选 | 只记了最终决定，没记约束和放弃原因 | 决策必须写全：备选方案、当时约束、放弃原因 |
| 复盘写成了流水账 | 凭记忆重写，而不是从日报逐层提炼 | 周复盘先读本周全部日报再动笔；没有事实写"无记录" |

## 硬性边界

- `04_日报素材/`、`05_文档原文/`、`07_附件/` **只读**；要提炼就把结论写到提炼层。
- 完成分四层：`已提交 ≠ 已上线 ≠ 已验收 ≠ 已见效果`，不许合并成"已完成"。
- 链接用标准 Markdown 相对路径（带 `.md` 后缀），Obsidian 和 GitHub 网页都能点。
- 库中尚无对应笔记时提醒用户是否新建，**不要写空链接**。
- 删除或覆盖已有文件、大改目录、配置 Git / 公开仓库、涉及账号证件 —— **全部先问用户**。
- 禁止写入：密码、令牌、Cookie、验证码、私钥、完整身份证号、银行卡号；以及**没有来源却伪装成事实的内容**。

## 捆绑资源

- `references/rules.md` —— 完整 AI 操作规则，写入前读
- `references/build-brief.md` —— 10 个核心入口文件的内容合同
- `assets/skeleton.txt` —— 目录骨架清单
- `assets/templates/` —— 日报、周复盘、月复盘、决策、经验卡片五个模板

## 命名斜杠命令

Claude Code 插件方式安装后，有四个现成口令（命令定义在仓库 `commands/` 目录，可自行增改）：

| 命令 | 做什么 |
|---|---|
| `/日报` | 写今天的日报（五段：今天完成、证据、新判断、待确认、下一步） |
| `/周复盘` | 先读本周全部日报，只从日报提炼周复盘 |
| `/记一下` | 把一件事记进行动总览：查重 → 分类 → 写齐十字段 |
| `/体检` | 跑体检脚本并解读结果，异常波动要核实 |

## 自检

若用户已 clone 本仓库，可运行 `python tools/vault_health_check.py --root .` 做断链、字段、状态和敏感信息检查（Windows 也可双击 `tools/health-check.cmd`）。
